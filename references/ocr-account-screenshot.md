# OCR读取券商账户截图

当用户通过WeChat发送持仓/账户截图（JPEG/PNG）时，可用OCR快速提取关键数据，无需用户手动输入。

## 前置条件

```bash
# 安装tesseract及中文语言包
sudo apt-get install -y tesseract-ocr tesseract-ocr-chi-sim
```

## 使用流程

### Step 1: 确认图片路径

用户发送的图片由平台自动下载到 `~/.hermes/image_cache/` 目录，文件名格式为 `img_<hash>.jpg`。

### Step 2: OCR识别

```bash
tesseract /home/agentuser/.hermes/image_cache/img_<hash>.jpg /tmp/ocr_output -l chi_sim 2>&1
cat /tmp/ocr_output.txt
```

### Step 3: 解析关键字段

中文券商APP截图通常包含以下关键字段（OCR可能因排版而顺序错乱，需手动对应）：

| 字段 | OCR中关键词 | 说明 |
|:----|:----------|:----|
| 标的名称 | 出现在表头或每行开头 | 如「港美互联网LOF」「港股通科技30ETF」 |
| 持仓数量 | 「持仓」附近数字 | 注意区分「持仓」和「可用」 |
| 现价 | 「现价」「最新」附近数字 | 格式通常为 X.XXX 或 XX.XX |
| 成本价 | 「成本」「成本价」附近数字 | 同上 |
| 持仓盈亏 | 「盈亏」「浮动盈亏」 | 可能包含+/-号和百分比 |
| 市值 | 「市值」附近数字 | 有时在最右列 |
| 可用资金 | 「可用」「余额」 | 通常在表格底部 |

### Step 4: 常见OCR错误及纠正

| 错误类型 | 表现 | 纠正方法 |
|:--------|:----|:--------|
| 数字混淆 | 5→s, 0→o, 8→B | 根据上下文推断，或用市值÷份额反算现价 |
| 百分比号误读 | 「-16.61%%」多了一个% | 去掉多余的%，取第一个 |
| 中文识别错 | 「持仓公亏」→ 持仓盈亏 | 行业黑话纠正 |
| 表格错行 | 现价列和成本列混在一起 | 用市值÷持仓数反算现价验证 |

### Step 5: 数据验证（用市值反推）

```
现价 ≈ 市值 ÷ 持仓数量
成本价 ≈ (市值 - 盈亏) ÷ 持仓数量
```

示例：
- 港美互联网LOF: 市值11,151 ÷ 持仓5,400 = 2.065 ✅ 吻合现价
- 港股通科技30ETF: 市值5,888 ÷ 12,500 = 0.471 ✅

### Step 6: 更新memory

```markdown
memory:
- 标的A: N份 @ 成本X.XXX，现价Y.YYY，浮亏Z元(W%)
- 标的B: ...
- 可用资金: ~XXX元（如有）
```

### ⚠️ 局限

- tesseract对中文截图OCR准确率约70-80%——关键数据（价格、数量、金额）必须用市值反推验证
- 如果反推结果与OCR读数偏差>5%，重试OCR或请用户手动确认
- 截图不包含历史成交记录，仅限于当前持仓快照
