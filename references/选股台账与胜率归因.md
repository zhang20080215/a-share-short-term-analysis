# 选股台账与胜率归因（让"提胜率"变得可度量）

> **2026-08-06 新增（补第四支柱）。** "提高胜率"必须先**能度量胜率**。原「推荐复盘请求」靠
> `session_search` 事后重建，**有损、不带维度**——无法回答"哪种 setup / 哪个情绪阶段 / 哪个模式
> 真的赚钱"。本文件建一个**追加式选股台账**：每次推荐即落一行，带模式/情绪阶段/形态维度，
> 事后按维度算胜率+期望+盈亏比，形成"**度量→归因→反哺选股**"的闭环。
> 相关：[[情绪周期与自动模式路由]]（emotion_phase 来源）、[[热点参与决策树]]（setup 枚举来源）、
> [[资金效率与轮动纪律]]（高期望 setup → 上调确定性档预算）、[[持仓账本与schema]]（持仓 vs 台账的分工）。
> 工具：`templates/picks-ledger.py`。

---

## 1. 台账 schema（picks.jsonl，追加式，一行一 JSON）

**为什么是 append-only JSONL**：推荐是流水事件，只追加不改写，最耐用、最不易损坏、便于跨会话累积。

```json
{"id":"20260806-1","date":"2026-08-06","code":"sh600584","name":"长电科技",
 "mode":"激进","emotion_phase":"主升期","emotion_temp":64,
 "setup":"首板龙头","sector":"半导体封测",
 "entry":38.5,"stop":36.2,"target":44.0,
 "bought":true,"status":"open","exit":null,"pnl_pct":null,"hold_days":null,"note":""}
```

| 字段 | 含义 | 取值 |
|:---|:---|:---|
| `mode` | 出该票时的模式 | 默认 / 激进 / 成长 |
| `emotion_phase` | 出票时情绪阶段 | 冰点/修复/发酵/主升/高潮/退潮（[[情绪周期与自动模式路由]]） |
| `emotion_temp` | 出票时温度分 | 0–100 |
| `setup` | 形态/参与点类型 | 见下枚举（[[热点参与决策树]]） |
| `bought` | 用户是否真买 | true/false（false=推荐但没买，评推荐质量用） |
| `status` | 结果 | open / win / loss / flat |

**setup 枚举（固定，便于归因不发散）：**
`首板龙头` `龙头回踩低吸` `龙二龙三补涨` `关联子板块补涨` `横盘突破` `大阳回踩` `超跌反弹`
`左侧埋伏` `趋势高潮参与` `其它`

**胜负定义（短线，净成本后；工具默认阈值）：**
- `win`：实现 pnl% ≥ **+1.0%**（或触及 target）
- `loss`：pnl% ≤ **−1.0%**（或触及 stop）
- `flat`：−1.0% < pnl% < +1.0%
- `open`：未平仓（不计入胜率，用 [[持仓账本与schema]] 看浮盈）

## 2. 追加纪律（写入选股硬前置）

**每次给出建仓/追涨推荐 → 立即追加一行台账。** 这是硬前置的一步，缺则流程未完成：
```
□ 追加台账：picks-ledger.py add（记 mode/emotion_phase/emotion_temp/setup/entry/stop/target/bought）
```
- 用户没采纳的推荐也记（`bought:false`）——用于分别评"推荐质量"和"执行质量"。
- **跨天更新**：清仓/止损/到目标后 → `picks-ledger.py close`，落 exit + 自动判 win/loss/flat。
- emotion_phase / emotion_temp 直接取 Step 1 情绪路由当次的输出，零额外成本。

## 3. 胜率归因（度量 → 找出"哪种打法真赚钱"）

`picks-ledger.py report --by {mode|emotion_phase|setup|sector}` 输出每个维度：

| 维度值 | N | 胜 | 负 | 平 | 胜率% | 平均盈亏%(期望) | 盈亏比 |
|:---|:--:|:--:|:--:|:--:|:--:|:--:|:--:|

**关键读法（避免被单一指标骗）：**
- **只看胜率会骗人**——低胜率 + 高盈亏比仍可正期望。**以"平均盈亏%(期望)"为主判据**，胜率+盈亏比辅助。
- 样本 < 10 的维度值：**参考，不下结论**（噪声大）。
- 分 `bought:true`（真实战绩）与 `bought:false`（推荐质量）两套看，别混。

---

## 4. 反哺选股（闭环的关键，不是记完就算）

归因结果要回流到前面三支柱：

```
某 setup 样本≥10 且 期望为负     → 该 setup 降级：加约束或停用（如"高潮期追跟风"若实测负期望，坐实禁令）
某 emotion_phase 期望系统性为负  → 该阶段自动降激进度（回填 [[情绪周期与自动模式路由]] 护栏）
某 setup 期望显著为正且样本足     → 接 [[资金效率与轮动纪律]] §1，该类信号上调确定性档/风险预算
某 mode 长期跑输                  → 检讨该模式触发条件是否过松
```

> 这条闭环才是"**提高胜率来赚钱**"的引擎：不是拍脑袋更激进，是**用自己的实测数据**决定
> 在哪种情绪阶段、用哪种 setup、下多大注——数据说哪种打法赚钱，就往哪种倾斜。

## 5. 与「推荐复盘请求」「持仓账本」的分工

| | 选股台账（本文件） | 推荐复盘请求(SKILL.md) | 持仓账本([[持仓账本与schema]]) |
|:---|:---|:---|:---|
| 记什么 | **每一次推荐**(含没买的) | 汇总复盘的**触发流程** | **当前持仓**实时状态 |
| 何时写 | 推荐即追加 | 用户问"评估胜率"时 | 调仓即更新 |
| 数据源 | 结构化台账(权威) | **优先读台账**，session_search 仅兜底 | 持仓 memory |
| 产出 | 按维度胜率+期望归因 | 面向用户的复盘汇总 | 浮盈/距止损/区间位 |

**「推荐复盘请求」升级**：以本台账为**权威数据源**，`session_search` 退为台账缺失时的兜底。

## 6. 常见陷阱

| 陷阱 | 纠正 |
|:---|:---|
| ❌ 只统计买了的赚没赚 | 也记没买的(bought:false)，分开评推荐质量 vs 执行质量 |
| ❌ 只看胜率 | 以期望(平均盈亏%)为主，低胜率高盈亏比可正EV |
| ❌ 样本不足就下结论 | <10 只参考不定论 |
| ❌ 记完不反哺 | 归因结果必须回填护栏/确定性档/setup 降级，否则白记 |
| ❌ 台账与持仓账本混用 | 台账记"所有推荐流水"，持仓账本记"当前持仓"，职责不同 |
